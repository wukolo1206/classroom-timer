## 二、專案背景

### 2.1 這是什麼

國小導師用的單檔 HTML 班級工具（教室大螢幕＋導師筆電）。「秩序登記」分頁：畫面是座位表，老師點某位學生，選一個檢查項目（如「坐姿不良」），該生該項次數 +1。右側有當日／本週／全部的統計，下方有統計表、CSV 匯出、複製報告。

有兩個版本，**程式碼是各自維護的兩份複本**（改一份不會自動帶到另一份）：

| 版本 | 資料存放 | 部署 |
|---|---|---|
| 408 班版 `index.html` | 瀏覽器 localStorage ＋ 同步到 Google 試算表 | 整頁由 Google Apps Script `doGet()` 提供（`HtmlService.createHtmlOutputFromFile`），同一份檔案也放 GitHub Pages 當離線備援（偵測不到 `google.script.run` 就是本機模式） |
| 全校通用版 `universal.html` | 只有 localStorage（key 一律加 `ctu_` 前綴，因為同網域還有其他工具） | GitHub Pages |

### 2.2 現有資料格式（408 版與全校版相同）

- localStorage `seatCheckRecords`：`{ '2026-10-10': { '5': { 'tilt': 2, 'c1788…': 1 } } }`（日期 → 座號 → 項目代碼 → 次數）
- 舊版曾存 `{ 座號: [項目代碼,…] }`，讀取時 `normalizeSeatDay()` 轉成次數。
- 檢查項目、座位表、分頁順序存 Apps Script DocumentProperties（408 版）。
- 選定日期：`seatActiveDate`（日期列是當週週一～週五按鈕，預設今天）。
- 統計範圍 `seatStatsRange`：all／weekly／today／7／30；右側摘要 `seatSummaryRange`：today／week／all。

### 2.3 408 版同步機制（重點）

- 試算表「上課表現紀錄」分頁欄位（**順序固定**）：`A 日期 | B 座號 | C 姓名 | D 項目 | E 次數 | F 最後更新 | G 項目代碼`。一天一人一項一列。G 欄是比對用的 key（項目可改名）。
- 前端每次登記，把**該格的絕對次數**排進 localStorage 佇列 `seatSyncQueue`：`{ date, seat, name, key, label, count }`，同一格只留最新一筆；有單工鎖，一次送一筆；失敗 15 秒重試；成功時只有佇列頭仍是剛送出那筆才移除。
- 後端 `setSeatCount(date, seat, name, itemKey, itemLabel, count)`：找 A＋B＋G 相同的列，改 E 欄為 count；0 就刪列；找不到就新增列。
- 開分頁時 `getSeatBundle()` 讀回全部列 → `{ date: { seat: { key: count } } }`；前端與本機**逐格取較大值合併**，本機比試算表大的格子補送。
- 另有：清除某日（`clearSeatRecords(date, seat?)`）、清除全部、匯入 JSON（合併／覆蓋）、匯出 CSV、依日期區間刪除。

### 2.4 不能動的地方

- 同一份試算表裡有老師每天在用的 9～1 月聯絡簿分頁，**任何程式只能寫「上課表現紀錄」分頁**。
- 「上課表現紀錄」**A～G 欄順序與 G 欄不可改**。
- 同步一律送**絕對值**，不可改回 +1（重送會算錯，實際發生過）。
- 部署一律用既有部署 ID（不可產生新網址）。
- 全校版只能寫 `ctu_` 開頭的 key。

## 1. 要做到什麼

1. 秩序登記**每一節課從 0 開始記**：座位表上看到的次數是「這一節」的，不再是整天累加。
2. 打開時**依作息自動跳到現在這一節**，也可以手動點別的節次（補登）。
3. 統計可以選看：**某一節／某一天全部節次／自訂日期範圍／只看某幾節**。
4. 舊紀錄（沒分節的）全部保留，歸在「未分節」，看得到、改得了。

## 2. 節次與作息

### 2.1 時段

| 代碼 | 試算表 H 欄文字 | 時間 |
|---|---|---|
| `m` | 早自習 | 07:40–08:40 |
| `1`～`4` | 第1節～第4節 | 08:40–09:20、09:30–10:10、10:30–11:10、11:20–12:00 |
| `n` | 午休 | 12:00–13:30 |
| `5`～`7` | 第5節～第7節 | 13:30–14:10、14:20–15:00、15:20–16:00 |
| （空） | （空白） | 未分節（舊紀錄） |

- 代碼與 H 欄文字**固定雙向對照**（`SEAT_PERIODS` 常數，兩版與後端同一份定義）。
- 作息時間是程式內常數（全校同一個學校、同一套鐘聲），標【可自行修改】；**不做畫面上的作息編輯**（原 v0.1 的「⚙️ 修改」取消），也就沒有雲端設定載入順序的問題。常數由測試檢查：時間遞增、不重疊、代碼不重複。
- 時間一律用使用者電腦的本地時間（台灣）。

### 2.2 自動／手動

- 有兩種狀態：**自動**（跟著時間走）與**手動**（老師點了某一節）。
- **自動**：每分鐘檢查一次，只有在「選的日期是今天」而且**沒有開著登記彈窗**時，才切到現在的節次；跨午夜時日期也跟著換到新的今天。判斷規則：每節從開始時間算到下一節開始（下課算剛結束那節）；07:40 前算早自習、16:00 後算第 7 節。
- **手動**：點任何節次按鈕（或看別天）就進入手動，不再自動跳。畫面顯示「手動・按這裡回到自動」。
- 回到自動的方式：按「回到自動」、切到別的分頁再切回來、或日期點回今天。

## 3. 資料格式與後端

### 3.1 時段鍵

```
'2026-10-10'      ← 未分節（舊紀錄，原樣保留）
'2026-10-10#3'    ← 第 3 節
'2026-10-10#m'    ← 早自習
```

- 本機 `seatCheckRecords` 的頂層鍵改為時段鍵，下層結構不變。
- **集中三個函式**處理，其他程式一律呼叫、不自行拆字串：`slotKey(date, period)`、`parseSlot(key) → { date, period }`、`slotDate(key)`。
- 畫面狀態分開存：`seatActiveDate`（日期）、`seatActivePeriod`（節次代碼或 `''`＝未分節）、`seatViewAll`（全天檢視）。寫入目標＝`slotKey(seatActiveDate, seatActivePeriod)`；全天檢視時**沒有寫入目標**。

### 3.2 試算表 H 欄

- 「上課表現紀錄」最後面新增 **H 欄「節次」**，A～G 不動。後端第一次讀寫時若 H1 是空白，補表頭「節次」（只寫這一格）。
- 一列＝日期＋座號＋項目＋節次。`setSeatCount(時段鍵, …)` 參數不變，後端用 `parseSlot` 拆開，比對 A＋B＋G＋H。
- 讀取時 H 欄文字經對照表轉代碼；**對照表以外的文字**保留成獨立時段（鍵 `日期#?原文`，畫面顯示原文），不併入未分節。

### 3.3 清除（範圍明確化）

| 操作 | 範圍 | 後端 |
|---|---|---|
| 清除本節 | 選定日期＋選定節次（含「未分節」） | `clearSeatSlot(時段鍵, 座號?)`：比對 A＋H |
| 清除全天 | 選定日期的所有節次＋未分節 | `clearSeatDay(日期, 座號?)`：只比對 A |
| 依日期區間刪除 | 區間內所有節次（確認視窗寫明「包含全部節次」） | 逐日呼叫 `clearSeatDay` |
| 清除全部 | 全部 | `clearSeatAll()`（不變） |

- 舊 `clearSeatRecords(date, seat)` 保留給還開著的舊頁面用：語意＝只清**未分節**（H 空白）的列，所以舊頁面不會誤刪分節資料。

### 3.4 整批匯入

- 新函式 `importSeatRecordsV2(rows)`：每列 `[時段鍵, 座號, 姓名, 項目名稱, 次數, 項目代碼]`，後端驗證每個時段鍵（日期格式、節次代碼），拆成 8 欄，清空 A～H 舊資料後一次寫入，寫完讀回核對列數。
- 舊 `importSeatRecords(rows)` 改為**直接拋錯**「頁面版本太舊，請重新整理後再匯入」——避免還開著的舊頁面用 7 欄資料把分節紀錄整批蓋掉。
- 匯入前前端照舊自動下載備份。

### 3.5 破壞性操作與佇列同序

- 清除、整批匯入**改成排進同一條同步佇列**（工作類型：`count`／`clearSlot`／`clearDay`／`clearAll`／`import`），由同一個單工鎖依序送出。
- 排入清除或匯入時，先把佇列裡**受影響範圍內的 `count` 工作移除**（清除本節移除該時段；清除全天移除該日所有時段；匯入與清除全部移除全部）。這樣清除後不會被舊次數寫回，匯入也不會被舊次數覆蓋。
- 舊佇列中沒有 `type` 的工作視為 `count`（相容既有佇列）。

### 3.6 本機合併與統計

- 拉取時合併照舊（逐格取較大值），鍵是時段鍵。
- 所有「日期」計算（日期列、近 N 天、每週統計、區間刪除）一律經 `slotDate()`；**天數按不同日期去重**，人數按座號去重；區間篩選同時檢查起日與迄日。

## 4. 畫面

### 4.1 登記

```
[ 週一 10/6 ] … [ 週五 10/10 ]                               ← 日期列（原有）
[早自習][第1節][第2節][●第3節 ²][第4節][午休][第5節][第6節][第7節] [未分節 ⁵] [全天]
 第 3 節（10:30–11:10）・自動            ← 或「手動・回到自動」
```

- 點座位登記到「選定日期＋選定節次」。節次按鈕右上小數字＝該節總次數。
- **「未分節」按鈕只在該日期有舊紀錄時出現**，可查看、扣減、清除，也可補登（就是一個時段）。
- **「全天」只供觀看**：座位顯示全天加總；點座位、復原、清除本節都停用並提示「請先選一節」；「清除全天」可用。
- **彈窗與復原記住時段**：開彈窗時記下當下時段鍵，彈窗內所有加減都寫到這個時段，期間自動切節暫停；復原堆疊每筆存 `{ 時段鍵, 座號, 項目 }`，復原時扣回原本那一節（畫面不在那一節時提示「已復原第 2 節的一筆」）。

### 4.2 統計

- 範圍按鈕保留（今日／近 7 天／近 30 天／全部／每週統計），新增「自訂」（起～迄）。
- 節次篩選：預設「全部節次」，另有「本節」「自訂」；選自訂才展開節次複選（含「未分節」）。按鈕旁持續顯示篩選摘要，例如「近 7 天・第 3 節」。
- **統計表、複製報告、CSV 都套用同一組篩選**；右側摘要（今日／本週／全部／本節）是獨立的。
- **CSV 定義**：
  - 「匯出統計 CSV」＝現有格式（每人一列的彙總），開頭兩行註明「日期範圍」與「節次」。
  - 新增「匯出逐節明細 CSV」＝一筆一列：日期、節次、座號、姓名、項目、次數。

## 5. 驗收

功能：
- 第 3 節登記 2 次 → 第 4 節是 0 → 回第 3 節是 2；全天顯示 2，全天模式點座位／復原不會寫入。
- 第 2 節登記後切到第 3 節按復原 → 扣回第 2 節，第 3 節不變。
- 彈窗開著時跨過節次時間 → 彈窗內的加減仍寫到原節次。
- 08:45 開啟→第 1 節；10:15→第 2 節；手動點第 4 節後時間到第 5 節仍停在第 4 節；按「回到自動」跳回現在節次。
- 同日第 3、4 節與未分節都有資料 → 清除本節（第 3 節）只刪第 3 節；清除全天三者都刪。
- 舊資料在「未分節」看得到、可扣減；全天加總含舊資料。
- 統計：「近 7 天＋第 3 節」只算第 3 節；同一天兩節只算 1 天；每週統計不因兩節而分成兩週。
- CSV 兩種都正確；JSON 備份→還原後時段鍵不變。

408 同步（Node 模擬試算表＋瀏覽器內模擬 google.script.run）：
- H 欄寫入、舊列（H 空白）讀回未分節、H 為對照表外文字保留為獨立時段。
- 重送同一筆不重複；清除與 count 工作同序，清除後舊次數不會寫回。
- 匯入 V2：資料列變少時不殘留舊列與舊 H；舊 `importSeatRecords` 會拋錯。
- **舊頁面＋新後端**：只送日期的 `setSeatCount` 寫到未分節；舊 `clearSeatRecords` 只清未分節。
- 兩版既有測試全部通過。

## 6. 部署與回復

GAS 版的前端頁面與後端在**同一次部署**一起更新，所以不會出現「新頁面配舊後端」；需要處理的是**部署當下還開著的舊頁面**與**本機佇列裡的舊工作**，已由 §3.3（舊清除只清未分節）、§3.4（舊匯入拋錯）、§3.5（舊工作視為 count，只寫未分節）處理。

部署前：
1. 用 Sheets API **唯讀**匯出「上課表現紀錄」A～G 全部列到本機 CSV（不在試算表新增任何分頁）；GAS 版按「匯出 JSON」下載一份本機紀錄。
2. Node 模擬與瀏覽器測試全過。

部署後：
1. 開 GAS 網址，在**第 1 節**點一位學生一次 → 試算表多一列且 H＝「第1節」、A～G 格式不變 → 扣回 0，該列刪除。
2. 請使用者把教室大屏與筆電都重新整理一次（讓舊頁面換成新版）。

回復：
- **不可退回舊 7 欄後端**：舊 `setSeatCount` 只比 A＋B＋G，會把不同節次的列當成同一列覆寫。

## 五、請特別幫忙看的問題

1. §3.5 把清除與匯入排進同一條佇列：佇列存在 localStorage、跨重新整理保留。若「清除全天」排入後、送出前，老師又在同一天登記新的一筆，順序會是 clearDay → count，結果正確嗎？反過來 count 在 clearDay 前面但還沒送出，被 §3.5 的「移除受影響 count」刪掉，本機畫面與試算表會一致嗎？
2. §3.3 舊 `clearSeatRecords` 改成「只清未分節」：舊頁面的老師按「清除今天」，畫面上清空了，但試算表的分節資料還在，下次拉取又被合併回來（取較大值）。這個行為可以接受嗎？有沒有更好的處理？
3. §3.4 匯入 V2「清空 A～H 再寫入、讀回核對列數」：寫入一半失敗（GAS 逾時）時，試算表會處於半空狀態。有沒有低成本的保護（不能新增分頁）？
4. §6 回復開關 `SEAT_PERIOD_UI` 關掉後，畫面只顯示全天：這時新登記要寫到哪個時段？會不會和未分節混在一起？
